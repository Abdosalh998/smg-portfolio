# Prompt 0 — Project Overview

## Project Name

SMG Turbo Fan Landing Page

---

## Project Goal

Develop a premium, modern, responsive Landing Page for **S.M.G. Turbo Fan Central Ventilation Systems**.

The website represents a company specialized in Central Ventilation Systems, HVAC Solutions, Industrial Fans, Air Handling, Manufacturing, Installation, and Maintenance.

This project is not just a landing page; it should serve as a professional digital presence that highlights the company's services, products, previous work, and allows visitors to contact the company easily.

---

## Design Inspiration

The design philosophy should be inspired by the following website:

https://smgturbofan.com/

Do **NOT** copy the website.

Instead, create a new implementation that follows the same overall feeling regarding:

* Professional industrial appearance
* Corporate color palette
* Modern typography
* Premium spacing
* Hero section style
* Smooth animations
* Scroll animations
* Hover effects
* Image presentation
* Cards layout
* CTA sections
* Responsive behavior
* Modern UI/UX

The final website should feel premium and trustworthy.

---

## Technology Stack

### Frontend

* React.js
* React Router
* Responsive Design
* Mobile First
* Lazy Loading
* SEO Friendly
* Reusable Components

### Backend

* Node.js
* Express.js
* REST API
* JWT Authentication

### Database

MongoDB running as a Docker Image.

### Reverse Proxy

Nginx

---

## Project Architecture

The project consists of two major applications.

### 1. Landing Page

Visible to visitors.

Contains all public sections.

All displayed data must be loaded dynamically from the backend APIs.

No hardcoded data except the initial seed.

---

### 2. Admin Dashboard

Accessible only after authentication.

The dashboard is responsible for managing every part of the Landing Page.

Everything visible on the website must be editable from the Dashboard.

---

## Dashboard Responsibilities

The Dashboard will manage:

* About Us
* Why Choose Us
* Services
* Applications
* Products
* Gallery
* Contact Information
* Inbox
* Footer
* Website Settings

Every module should support full CRUD operations.

---

## Dynamic Content

No section should contain static content.

Everything should come from MongoDB through REST APIs.

The backend should seed the database with the initial data only on first deployment.

After that, the Dashboard becomes the only source for managing website content.

---

## Contact System

The Contact Form must send submissions to the backend.

Every submitted message should automatically appear inside a dedicated **Inbox** module in the Dashboard.

---

## Security

Use JWT Authentication.

Protect every Dashboard API.

Validate all incoming requests.

Secure file uploads.

---

## Performance

The project should be production-ready and optimized for:

* Performance
* SEO
* Security
* Scalability
* Clean Architecture
* Reusable Components

---

## Development Rules

While building every module:

* Follow Clean Code principles.
* Use reusable React components.
* Separate frontend and backend concerns.
* Keep APIs RESTful.
* Handle loading and error states.
* Write scalable and maintainable code.
* Use consistent naming conventions.
* Keep the UI responsive across all devices.
* Ensure every feature is fully connected between Frontend, Backend, and MongoDB.

This overview defines the complete vision of the project. All upcoming prompts will describe each module independently and should follow these architectural and development rules.
